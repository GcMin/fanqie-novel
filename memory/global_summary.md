# 全书压缩摘要

用于让 AI 在不重读全部历史正文的情况下快速掌握已经发生的主线。

## 更新规则
- 每章结束后可补充必要事实。
- 至少每 10 章重新压缩整理一次。
- 只保留对未来仍有影响的信息，不写流水账。

## 当前摘要（第70章后）

28岁的周衡在原物业工程岗位调整后，以外包新人身份进入临江市夜间综合服务中心。第一夜00:17，他接到“青梧苑13栋704”生活噪音工单，但现行地图、物业、门岗和普通资料都只承认青梧苑有12栋。资深外勤梁策坚持保留原地址，不让周衡把13栋改成12栋；调度员夏宁保存原始热线、页面、时间和不同媒介副本。三人的工作方法随后逐渐固定：先处理现实安全与正常业务，再按来源、业务层、时间和权限保存证据；不能为了把故事说圆而覆盖原始字段，也不能让单一材料越级证明完整机制。

第一夜，12栋后停车区在约01:03出现一条固定监控看不到、手机却能拍到的道路，周衡与梁策进入具有门禁、电表、公告、住户和长期生活痕迹的13栋。704住户刘桂兰确认自己是投诉人，并坚信七层楼上一直存在804；02:00后原本封顶的位置逐渐形成额外楼梯，二人最终进入新增八楼804。804旧照片可独立读出“永安里居民区”和老式6栋入口，冲印时间为2015年。周衡由此披露自己长期记得童年住址“永安里6栋201”，但现实中的父母与常规资料一直否认这一住址。804未知男性还认为现实中已退休两年的原工程主管陈德福“刚去拿钥匙”，但该人的身份与陈德福为何被这样记住仍未解释。

第一卷后半形成两类可验证冲突。2015旧联动扫描最初写“青梧苑13栋”，同一电子源稍后变为12栋，而变化前打印的纸页暂时保留13栋。门岗王启明又把此前亲手发现的钥匙自然说成“12屋面”，现场却无提示读出实体标签“13屋面”；其本人01:49聊天照片和04:44当前照片都显示13屋面，但他不记得01:49拍摄行为。到第70章，王启明仍是F008唯一达到“具体事件记忆与本人保留记录/当前实体直接冲突”标准的样本，陈德福和梁策的长期记忆误差仍可以普通遗忘解释，不能擅自升级为普遍记忆规则。

704原工单在刘桂兰确认噪音已停后仍两次从正常办结恢复为处理中，无新热线时“最近诉求时间”继续刷新。Day 2 07:08，同一原工单当前投诉人变成周衡、地址变成永安里6栋201，但原工单号、刘桂兰00:17热线录音和联系电话仍保留，且没有周衡主动投诉记录。白班系统管理员只能确认07:08:11服务账号`svc_addr_route`执行过“未映射地址复核/责任路由重算”，地址来源ID为空且设计写回范围不含投诉人，因此它只是一处技术触点，不能证明生成了永安里6栋201或修改投诉人。**704当前字段始终只能证明系统此刻如此显示，不能反向作为历史住址证明。**

第二卷沿正常业务链重新核青梧苑历史。2015物业回访、维修单、中心外部流水、工程图E-07、住户/回访附件和夜联原册共同证明：二期13#曾作为独立建筑存在，刘桂兰13#704曾被正常处理。陈德福看完整工程图后能以专业判断确认13#是楼号，但自然记忆仍只记二期住宅7至12，且无法可靠回忆自己进入13#或经办具体维修。同期标准地址链却是另一套结果：2015夜联纸册已经记录“地址索引未检13栋 / 按原述转物业核址”，正式反馈资料确认维护侧因上游标准地址源没有对应新增/变更来源而未把13栋补入主表；更早的2015-08-31上游标准地址快照本身只列青梧苑1—12。由此形成一个可追溯的正常业务层分叉案例：物业/工程/住户/中心处置链保留13#，标准地址链却只承认1—12。原因未知，不能直接套用到永安里。

另一条主线来自62岁钱先生的旧地铁终点站失物工单。他坚称自己仍在“二号线槐荫路终点站”等候，而现实站点早已延伸并改名临江南。其口述无提示给出旧B口永安里、旧站务亭、尽端墙和旧式设施等历史细节；中心原录音还保存“终到槐荫路站”的旧清客广播，同分钟现行临江南却有正常列车到发。三人始终按人身安全优先，没有让老人进入轨行区或封闭区域。现实失物链最终确认其黑色帆布包早在前一运营日00:28随末班回库车辆被清出，车载视频又确认钱先生23:58从现行临江南下车。Day 3 02:16，既定固定联络电话铃声帮助现行站务人员在广告灯箱视觉折角里找到钱先生，02:52由家属陪同离开。其获救后仍坚持此前看见旧槐荫路环境，但这只保留为证词，不据此声明“过去空间/双空间机制”。
